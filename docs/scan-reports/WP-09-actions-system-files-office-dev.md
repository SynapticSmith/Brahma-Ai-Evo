## Executive Summary

Work Package 09 encompasses the core execution capability modules of Brahma AI Evo that interact with the host operating system, filesystems, office documents, developer toolchains, and reverse engineering engines.

While the higher-level agentic harness (`agent/runtime.py`, `agent/permissions.py`) enforces strict boundaries for modern harness tools, the legacy action implementations in `actions/` exhibit severe security and architectural bypasses. Most notably, unsanitized user/model inputs are formatted directly into PowerShell and AppleScript command lines (`actions/computer_control.py`, `actions/desktop.py`), arbitrary Python code generated by LLMs is executed using Python's `exec()` with a trivially penetrable pseudo-sandbox exposing `ctypes` (`actions/desktop.py`), and critical filesystem targeting allows policy scoping escapes via the uninspected `"name"` parameter in `file_controller.py`. Furthermore, multiple actions bypass the centralized `core/llm_gateway.py` (violating Invariant **I-21**) and read `api_keys.json` directly as plaintext, breaking compatibility with DPAPI secret encryption.

Remediation requires immediate parameter sanitization / AST parsing for process commands, updating `agent/spec.py`'s `PATH_ARG_KEYS`, disabling or re-engineering the `desktop_control` Python execution path to use isolated subprocess sandboxing, and deprecating redundant/dead action scripts.

## 1. Subsystem Architecture & Data-Flow Summary

The native capability actions in `actions/` serve as the execution engine for desktop manipulation, document processing, code execution, and system diagnostics. They are exposed to the AI model through two main channels:
1. **Core Desktop Tools Bridge (`core/desktop_tools.py`):** Acts as the primary adapter registering `ToolSpec` objects into `AgentRuntime`. It wraps action functions, performs dynamic or static tool classification (`read`, `write`, `device`, `network`, `exec`), and enforces workspace sandboxing for registered tools.
2. **Harness / Legacy Seam (`actions/`):** A collection of 25 modules containing utility functions, automation classes, and subprocess launchers.

```
       +--------------------------------------------------------------+
       |                   Model / Orchestrator                       |
       +--------------------------------------------------------------+
                                      |
                                      v
       +--------------------------------------------------------------+
       |               AgentRuntime.execute(call)                     |
       |  - Evaluates tool_class against agent_permissions.json       |
       |  - Validates path args in PATH_ARG_KEYS against workspace     |
       +--------------------------------------------------------------+
                                      |
                     +----------------+----------------+
                     |                                 |
                     v                                 v
       +----------------------------+    +----------------------------+
       |   Modern Harness Tools     |    |   core/desktop_tools.py    |
       | (agent/tools.py, run_cmd)  |    | (Adapters for actions/*)   |
       +----------------------------+    +----------------------------+
                     |                                 |
                     v                                 v
       +----------------------------+    +----------------------------+
       | agent.process.run_captured |    | actions/computer_control   |
       | (Job Object / Tree Kill)   |    | actions/file_controller    |
       +----------------------------+    | actions/desktop            |
                                         | actions/code_helper        |
                                         | actions/docx_tools ...     |
                                         +----------------------------+
                                                       |
                                           [DIVERGENT EXECUTION]
                                           - raw subprocess.run()
                                           - raw osascript / powershell
                                           - python exec()
                                           - direct genai.Client
```

### Architectural Seams & Invariant Violations Observed:
- **Command Dispatch Disparity (Invariant I-12 & I-24):** Unlike `agent/process.py:run_captured`, actions in `actions/` spawn unmanaged child processes via standard library `subprocess.run()`, `subprocess.Popen()`, and `os.system()`, bypassing process containment, job object grouping, and tree termination.
- **Path Validation Boundary (Invariant I-01):** `AgentRuntime.evaluate` extracts path arguments matching `PATH_ARG_KEYS`. Because `file_controller.py` separates directory navigation into `path` and `name`, an attacker or model can supply a benign workspace directory for `path` and an arbitrary destination (`../../.ssh/id_rsa`) for `name`, completely bypassing policy workspace confinement.
- **LLM Gateway Disparity (Invariant I-21):** While `actions/file_processor.py`, `actions/docx_tools.py`, and `actions/dev_agent.py` properly route LLM queries through `core/llm_gateway.py`, `actions/reverse_engineer.py` instantiates `google.genai.Client` directly, and `actions/office_generator.py` bypasses secret management by reading `api_keys.json` with `json.load`.

## 3. Invariant & Specific Audit Question Verdicts

### Invariant Checks

#### Invariant I-01: Single Permission Boundary (`AgentRuntime.execute`)
- **Verdict: VIOLATED / SEVERELY IMPAIRED**
- **Analysis:** While `AgentRuntime.execute` is invoked before reaching actions wired through `core/desktop_tools.py`, the path validation parameter inspection (`agent/spec.py:PATH_ARG_KEYS`) does not inspect `"name"`. In `actions/file_controller.py`, path resolution is executed as `target = (base / name) if name else base`. An attacker can specify a workspace directory as `path` and `../../.ssh/id_rsa` as `name`. `AgentRuntime` checks only `path` and grants access, allowing `file_controller` to read or overwrite files outside the workspace.
- Furthermore, `actions/desktop.py:desktop_control` exposes full desktop cleanup and file reorganization under `tool_class="device"`, bypassing `"write"` permissions.

#### Invariant I-12: Subprocess & Shell Safety
- **Verdict: VIOLATED**
- **Analysis:** Multiple modules execute raw command strings with shell interpreters without sanitization:
  - `actions/computer_control.py:245-249`: User/model provided `title` is interpolated into a PowerShell command string executed via `["powershell", "-NoProfile", "-NonInteractive", "-Command", script]`. Unsanitized quotes allow complete command injection.
  - `actions/desktop.py:150-155`: Unescaped `path` parameter interpolated directly into `osascript -e '... POSIX file "{path}"'`.
  - `actions/computer_settings.py:186-192`: Unquoted Linux brightness commands passed to `subprocess.run(..., shell=True)`.
  - `actions/brahma_dev_agent.py:48-55`: Executes unmanaged shell commands via `powershell -Command` on Windows and `subprocess.run(..., shell=True)` on Linux/macOS.

#### Invariant I-21: LLM Gateway Centralization
- **Verdict: VIOLATED**
- **Analysis:**
  - `actions/reverse_engineer.py:242-246`: Directly imports and instantiates `google.genai.Client(api_key=api_key)`. It does not use `core/llm_gateway.py`, bypassing token accounting, provider abstraction, retry logic, and circuit breakers.
  - `actions/office_generator.py:29-33`: Bypasses `core/secret_store.py` and reads plaintext `api_keys.json`, passing the raw API key into `llm_gateway.generate_content`.
  - `actions/brahma_dev_agent.py:319-322`: Directly parses `api_keys.json` with `json.load`.

#### Invariant I-24: Subprocess Tree Termination & Containment
- **Verdict: VIOLATED**
- **Analysis:** None of the subprocess invocations in `actions/code_helper.py`, `actions/dev_agent.py`, `actions/brahma_dev_agent.py`, `actions/open_app.py`, or `actions/file_processor.py` use `agent.process.run_captured`. None attach child processes to Windows Job Objects or POSIX process groups. If a spawned process hangs, timeouts kill only the immediate parent, leaking orphaned background processes and file locks.

- **Severity:** **CRITICAL**
- **Category:** Security / Command Injection
- **Location:** [`actions/computer_control.py:245-249`](file:///C:/Users/Admin/Brahma-Ai-Evo/actions/computer_control.py#L245-L249) in `focus_window()`

  ```python
      )
  ```
  The parameter `title` is taken directly from the tool call arguments and string-interpolated into a PowerShell command string. If an attacker or LLM passes:
  `title = '"; Start-Process powershell -ArgumentList "-c calc.exe"; #'`
  PowerShell evaluates the injected script syntax, escaping the COM object activation and executing arbitrary commands.
  A similar injection flaw exists in the macOS branch ([`actions/computer_control.py:256-263`](file:///C:/Users/Admin/Brahma-Ai-Evo/actions/computer_control.py#L256-L263)) where `title` is formatted into `osascript -e 'tell application "{title}" to activate'`.
- **Impact:** Complete system compromise. An unprivileged tool call approved under `tool_class="device"` can execute arbitrary PowerShell commands on the host machine.
- **Recommended Fix:**
  Replace PowerShell script interpolation with native Windows API calls via `pywin32` / `ctypes`:
  ```python
  import win32gui
  hwnd = win32gui.FindWindow(None, title)
  if hwnd:
      win32gui.SetForegroundWindow(hwnd)
  ```
  If PowerShell must be invoked, pass the parameter as an argument (`-Command "param($t) (New-Object -ComObject WScript.Shell).AppActivate($t)" -args $title`) rather than interpolating into the script string.

### WP-09-F02: Path Scoping Bypass via Unchecked `"name"` Argument in `file_controller`

- **Severity:** **CRITICAL**
- **Category:** Security / Authorization Bypass & Path Traversal
- **Location:** [`actions/file_controller.py:165-171`](file:///C:/Users/Admin/Brahma-Ai-Evo/actions/file_controller.py#L165-L171) in `file_controller()`, and [`agent/spec.py:35-50`](file:///C:/Users/Admin/Brahma-Ai-Evo/agent/spec.py#L35-L50) in `PATH_ARG_KEYS`
- **Evidence & Mechanism:**
  `AgentRuntime.evaluate()` inspects tool arguments matching `PATH_ARG_KEYS` to verify whether the target path lies within approved workspace boundaries.
  In `agent/spec.py`:
  ```python
  PATH_ARG_KEYS = (
      "path", "file", "filepath", "file_path", "filename", "cwd",
      "dir", "directory", "target", "source", "destination", "root", "workspace",
  )
  ```
  `"name"` is omitted from this tuple.
  In `actions/file_controller.py`:
  ```python
  base = self.resolve_path(path)
  target = (base / name) if name else base
  ```
  When the tool is called with `path="."` (or any valid workspace directory) and `name="../../.ssh/id_rsa"`:
  1. `AgentRuntime` checks `path="."`, verifies it is within the workspace, and evaluates the call as safe.
  2. `file_controller.py` combines `base / name`, resolving the target outside the workspace.
  3. `file_controller._is_safe_path(target)` checks only if `target.is_relative_to(Path.home())`. Since `.ssh/id_rsa` is inside the user's home directory, the check passes.
- **Impact:** Complete containment breach. The model or an attacker can read, write, or delete sensitive files across the entire user profile (SSH keys, AWS credentials, browser data, startup folders) while `AgentRuntime` policies believe the action is confined to the project workspace.
- **Recommended Fix:**
  1. Add `"name"` to `PATH_ARG_KEYS` in `agent/spec.py`.
  2. In `actions/file_controller.py`, enforce strict confinement:
     ```python
     target = (base / name).resolve() if name else base.resolve()
     if not target.is_relative_to(self.workspace_dir):
         return {"error": f"Path '{target}' is outside workspace boundary."}
     ```

### WP-09-F03: Arbitrary Python Code Execution via Broken Pseudo-Sandbox in `actions/desktop.py`

- **Category:** Security / Remote Code Execution
