# Epistemic Arbitrage Skill

## Overview
Drawn from Austrian economics, cognitive science, and strategic decision theory, this skill guides AI agents and system architects in identifying and exploiting "epistemic arbitrage" opportunities. Epistemic arbitrage occurs when there is a significant, exploitable delta between what a foundation model knows generally (broad internet training corpus) versus what it cannot see (local codebase state, runtime logs, private domain trade secrets, or unwritten user intent). Recognizing these asymmetries prevents costly hallucinations and unlocks massive leverage.

## The Tripartite Knowledge Matrix
1. **Model Domain (High Breadth, Zero Freshness)**: Generalized algorithms, API design patterns, language syntaxes, historical literature, standard libraries.
2. **Local Repository Domain (Zero Internet Knowledge, Exact Ground Truth)**: Specific database schemas, active environment configurations, git worktrees, private internal dependencies.
3. **User Intent Domain (Tacit Knowledge, High Context)**: Strategic priorities, non-technical constraints, unwritten business relationships, risk tolerances.

## Strategic Operational Rules
1. **Never Outsource Ground Truth to the Model**: Never ask an LLM "what does this function do?" without supplying the actual file content. Models hallucinate plausibly when forced to guess local state.
2. **Arbitrage the Synthesis Edge**: Use models where they possess massive comparative advantage: synthesizing vast syntax variations, translating cross-language paradigms, and detecting cognitive blindspots.
3. **Grounding as the Bridge**: Always bridge the epistemic delta via retrieval-augmented context (Second Brain, AST graphs, tools).
